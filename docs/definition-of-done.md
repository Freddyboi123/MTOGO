# Definition of Done

A task is considered done when the following criteria are met.

## 1. Functionality

- The functionality is implemented according to the acceptance criteria of the task.
- The functionality works as intended.

## 2. Code quality

- The code follows the code standards agreed by the project.
- The code is structured and follows the architecture of the project.
- Variables, methods and classes have meaningful names.
- No comments unless strictly necessary.
- An issue must solve a problem, not create a new one.

## 3. Testing

- Unit tests are implemented where relevant.
- Tests pass without errors.

## 4. Integration and Kanban

- There are no known critical errors.
- The CI build passes.
- The pull request has been reviewed and approved by at least one other group member.
- The pull request is merged into the review branch and the issue is closed as completed.
- Documentation affected by the change is updated, in English.

## Shared agreement

All group members are responsible for following the Definition of Done. A task may only be moved to the Done column on the Kanban board when the criteria above are met.
