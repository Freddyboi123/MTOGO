# Flow review 2026-11-24

Period: 17 to 24 November 2026, the second week of the project.

## Measurements

| Metric | Value |
| --- | --- |
| Throughput | 21 issues completed. Epics are not counted |
| Measurable | 20 of the 21 issues (95%) have both a Started and a Closed date. Last week it was 6 of 17 |
| Cycle time | 1.6 days on average, median 1 day |
| Longest cycle time | 6 days for #35, which waited in review |

## What the numbers do not show

- #28 has a cycle time of 5 days because the issue was closed late, after the work was merged.
- Some Started dates were set afterwards from comments and commits, because they were not set when the work started.

## Bottlenecks

- In Review is still where work waits. Pull requests waited for a review, and while they waited main moved, so they had to be updated again before they could be merged.
- A pull request based on another unmerged branch (#125 on #123, #131 on #129) made the bottleneck worse. #131 was merged into the wrong branch, and its changes did not reach main.
- Approvals are removed when new commits are pushed, so an updated pull request needs a new review.

## What worked

- Feature flags let us merge unfinished work without showing it to users.
- Splitting the work into epics, user stories and tasks made it clear what is left of each feature.
- Playwright end to end tests and smoke tests after deploy were added as quality gates.
- Monitoring with Prometheus and Grafana shows requests, response times and errors in production.

## Proposed actions

- Review open pull requests before starting new work, and review within a day.
- Create branches from the newest main and merge main into the branch before merging.
- Do not base pull requests on unmerged branches.
- Turn on auto merge in the repository, so a pull request is merged as soon as it is approved and does not fall behind main.
- Set the Started date when an issue is moved to In Progress.
