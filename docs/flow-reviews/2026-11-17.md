## What the numbers do not show

- The board was created on 11 November, after some of the work was done. Ten issues were registered and closed on the same day, so their dates say nothing about the real working time.
- Only 6 of the 17 completed issues have a Started date, so the cycle time covers about a third of the work.
- #42 was merged on 13 November but the issue was not closed until 16 November. The recorded cycle time is 3 days, the real one was less than a day.

## Bottlenecks

- In Review is where work waits. #35 has been in review since 12 November.
- Closing the issue after the merge is forgotten, which makes the cycle time look longer than it is and leaves open issues in the Done column.

## What worked

- Pull requests with review caught real issues. The review of the frontend led to #50, which moves all styling to CSS modules.
- The WIP limit of one issue per person was kept. WIP never went above 4.
- CI builds the backend and runs the tests on every pull request.

## Proposed actions

- Set the Started date when an issue is moved to In Progress, and close the issue when its pull request is merged.
- Review open pull requests before starting new work.
- Add the frontend build to CI (#56) and static analysis and test coverage (#28) as quality gates.
- Protect the review and main branches (#29).
